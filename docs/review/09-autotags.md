# 离线自动标签：词表、判定规则和标定

2026-10-12。代码：`src/core/autotag/`（词表 `vocabulary.ts`、判定 `assign.ts`、数据 `store.ts`），后台服务 `src/main/autotags.ts`。

## 做法

- **零网络**：标签的文字描述用 EmbeddingGemma 2 编码（和搜索框同一条 `encodeText` 路径），和图片 / 视频片段已存的 768 维向量比余弦。不需要额外模型、云服务或 Ollama。
- **词表 v1**：152 个标签，五类：场景 45、主体 48、类型 22、活动 25、时间 / 光线 12。每个标签有中英文名和 1–3 句描述（英文一句 + 中文一句，向量取平均）。
- **判定**（`assignLabels`）：
  1. 校正分 z =（余弦 − 该标签在本库的平均余弦）/ 本库合并标准差。有的标签（"全景""室内"）和什么图都挺像，减掉它自己的均值才公平；标准差把所有标签合在一起算，小库里逐标签的标准差不稳。
  2. 第一个标签 z ≥ 3；第二、三个 z ≥ 3.8；"活动"类再 +0.7（动作最容易看错）。
  3. 只看这张图余弦排前 3 的标签，且与第一名相差 ≤ 0.03。
  4. 每项最多 3 个。
- **视频 / 音频**：代表帧判一遍，各片段（画面 + 声音）也判一遍再合并；只在片段里出现、代表帧没有的标签要 z ≥ 4.5（片段向量混了声音和多帧，误判最多）。
- **基线**：从本库抽 400 条图片向量、400 条片段向量算；库变化超过 10% 重算。库里不到 20 项时先不打。

## 标定数据

三个库：演示库 34 项、公有领域视频素材 22 段、真实库 358 个视频帧（只读副本）。

| | 值 |
|---|---|
| 所有（图, 标签）余弦 | p50 0.650 · p90 0.681 · p99 0.723 · 最大 0.812 |
| 本库合并标准差 | 0.020–0.025 |

人工核对（看缩略图接触表逐个判断）：

| 规则 | 核对的标签数 | 对 | 精度 |
|---|---|---|---|
| 初版（z ≥ 3、top 3、差 ≤ 0.03，演示库 + 素材库全部） | 62 | 54 | 87% |
| 终版，演示库 + 素材库全部 | 44 | 41 | 93% |
| 终版，真实库抽样（每 6 个有标签的项取 1 个，36 项） | 45 | 41 | 91% |
| **终版合计** | **89** | **82** | **92%** |

初版错的主要是第二标签（"河流""白板""建筑"）和动作（大浪里的帆船被判成"冲浪"），所以收紧了第二标签和活动类。终版剩下的错：

- 演示库：博物馆陈列柜里的"小船"模型被判成"船"（勉强）；`EOS_70D` 湖景只判出"船"；`japanese-shop` 只判出"霓虹"（店面灯箱，算勉强对）。
- 真实库："车站"一类的室内地铁里，人物合影被判成"自拍"（半对：是人物照片，不全是自拍）；一张手持商品的近景判成"寺庙"；一张新疆坚果拼盘判成"甜点"；一张街头人像判成"人像"（对）。

覆盖率：演示库 23/34 项、素材库 17/22 段、真实库 210/358 帧至少有一个标签；平均每项 0.7–0.9 个。宁缺毋滥：没把握的就不打。

## 用户操作

- ✓ 确认：自动标签变成普通标签，之后重跑不会动它。
- × 删除：记住拒绝，这项内容以后不会再自动打上这个标签。
- 改名：标签变成用户自己的，不再跟词表走（不再随界面语言换名字）。
- 设置 → 通用 → 自动标签：开关（关掉会去掉还没确认的自动标签）、重新生成（拒绝记录保留）。

## 已知局限

- 词表是固定的；用户自己的概念（"老家""公司团建"）还是要手动打。
- 只有 v1 一套词表、一种规则；没有按库自适应地调阈值。
- 真实库全是同一次旅行的视频帧，题材集中（博物馆、市场、美食），不代表一般照片库。
- 标定脚本：`scripts/autotag-calibrate.cjs`（编码词表）、`autotag-eval.cjs`（按库出结果）、`autotag-eval-seg.cjs`（视频片段）、`autotag-sheet.cjs`（接触表）。
