### 回答正文

利益相关：下面说的 Vixel 是我自己写的，免费开源（MIT），按惯例先说清楚。

先回答「类似 Eagle 的免费替代」这个问题本身。Eagle 的强项是**收集和手工组织**：
浏览器扩展、标签体系、智能文件夹，这套它做了很多年，确实成熟。如果你的工作流以「收集 + 分类」
为中心，Eagle 值它的价格。

但如果你的痛点是「东西已经在硬盘里了，就是找不到」，可以试试另一条路：不整理，直接搜。

Vixel 做的事：

1. **原地索引你现有的文件夹**（只读，不导入、不搬家、不改名）。照片、视频、音频，
   以及 SVG / PSD / PDF / AI 设计文件。
2. **用一句话搜**：「海边的日落」「火箭发射」。视频按 32 秒一段编码（画面 + 声音），
   搜到直接跳到那一段——这是和 Eagle 差异最大的点，Eagle 的 AI 搜索只针对图片。
3. **图里的字能搜**：本地 PaddleOCR v5 + 结巴分词，截图、票据、视频里的招牌字幕都行。
4. **以图搜图**：拖一张截图进去，找到它出自哪个视频的哪一段。
5. **轻整理**：自动标签（离线生成，可增删）、人物（人脸聚类）、收藏、筛选（含颜色）、
   智能相册、相似照片清理。
6. **完全离线**：模型打包在安装包里（600 MB 的主要成分），没有账号、没有上传，断网可用。
   新版本还加了全局快捷键：任何应用里 ⇧⌘Space 呼出搜索面板。

免费开源，macOS（Apple Silicon）和 Windows（x64）都有：
https://github.com/RGB-loop/Vixel

几个如实的提醒：安装包未签名（macOS 要在隐私与安全性里「仍要打开」，Windows 过一下
SmartScreen）；Linux 还没测过；它不做 Eagle 资源库导入——定位是直接索引文件夹，
你可以两个一起用。搜索质量在仓库里有公开评测集（`npm run eval`），搜不准的例子欢迎发我。

## 二、文章式（专栏）

### 标题（选一）

1. 把 AI 搜索塞进一个完全离线的桌面应用，我踩过的坑
2. 不整理素材库：本地多模态检索的一种做法
3. 免费开源的 Eagle 替代品？聊聊 Vixel 的取舍

### 结构

1. 为什么「整理」是伪需求（检索成本 vs 组织成本）
2. 多模态检索的技术选型：EmbeddingGemma 2 + LiteRT-LM（GPU），文字 / 图片 / 视频段 / 音频同空间
3. 四路召回与融合：向量 ×2 + OCR BM25 + 文件名，RRF；自适应相关性门槛（宁可说没有，不硬凑）
4. 中文的特殊照顾：结巴分词 + FTS5（以及一个「分词静默失效半个版本」的教训）
5. 视频「跳到那一秒」：32 秒分段、每 4 秒一帧 + 音轨
6. 离线的工程化：模型内置、渲染进程断网、浏览器扩展只连 127.0.0.1
7. 诚实的限制：600 MB、未签名、Linux 未测、EPS 不支持、已知 bad case
8. 和 Eagle / Immich / Apple 照片 / DigUp 的对比表（事实项，不拉踩）

## 回复预案

- 「开源的意义？」——隐私承诺可验证：断网用，或读 `enforceOfflinePolicy`。
- 「比云相册强在哪」——不比「强」，比「不同」：数据不出设备是硬前提的人才需要它。
- 「准确率多少」——公开评测集 demo top-1 1.00 / footage 0.94（`npm run eval` 可复现），
  但更想要你的 bad case。
- 被问速度——不公布速度数字，机器差异太大；欢迎自己测。
